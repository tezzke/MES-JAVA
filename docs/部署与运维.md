# MES 部署与运维

## 1. 部署前提

生产环境需要 JRE 21（目录发布）或 Docker Compose（容器部署）、MySQL 8、持久化 SQLite 目录、TLS 反向代理和可靠备份介质。应用只应使用专用服务账号运行。

初始 `admin` 密码**没有默认值**。`MES_BOOTSTRAP_ADMIN_PASSWORD` 为空时不会创建管理员；禁止在代码、Compose、`start.bat`、日志或镜像中写入真实密码。

## 2. 环境变量

应用识别的变量：

| 变量 | 生产要求 |
|---|---|
| `MES_BUSINESS_DB_ENABLED` | 生产设为 `true`，启用 MySQL Flyway 和业务域 |
| `MES_BUSINESS_DB_URL` | MySQL JDBC URL；显式指定数据库、UTF-8 和 UTC 时区 |
| `MES_BUSINESS_DB_USERNAME` | 业务库账号 |
| `MES_BUSINESS_DB_PASSWORD` | 非空强密码，从秘密管理注入 |
| `MES_TELEMETRY_DB_URL` | SQLite JDBC URL；容器默认为 `jdbc:sqlite:/app/data/mes.db` |
| `MES_BOOTSTRAP_ADMIN_PASSWORD` | 仅空库首次引导使用；无默认值，轮换后删除 |
| `MES_SESSION_COOKIE_SECURE` | TLS 生产环境必须为 `true` |
| `MES_ALLOWED_ORIGINS` | 允许携带凭据的精确 Origin，多个值用逗号分隔 |
| `MES_DEVICES_CONFIG` | 可选，外置 `devices.json` 的绝对路径 |
| `MES_MODBUS_PROBE_ENABLED` | 现场只读探针开关，默认 `false` |
| `MES_MODBUS_PROBE_ALLOWED_CIDRS` | 启用探针时设置最小设备网段白名单 |
| `MES_MODBUS_PROBE_ALLOWED_PORTS` | 探针目标端口白名单，默认 `502` |
| `MES_MODBUS_PROBE_MAX_CONCURRENT` | 探针并发上限，默认 `2`、最大 `16` |

Compose 另外读取 `MYSQL_DATABASE`、`MYSQL_USER`、`MYSQL_PASSWORD`、`MYSQL_ROOT_PASSWORD`，并设置 `SPRING_PROFILES_ACTIVE=prod` 和 `TZ=Asia/Shanghai`。示例见 [`deploy/.env.example`](../deploy/.env.example)。示例密码故意为空，Compose 会拒绝空的 MySQL 密码。

不要在命令行参数中传密码，因为进程列表和历史可能泄漏。优先使用容器秘密、服务管理器的受限环境或企业秘密管理系统。

## 3. MySQL 建库与最小权限

当前应用使用同一个账号运行 Flyway 和业务 SQL，因此该账号需要本 schema 内的数据权限与迁移 DDL 权限，但不需要全局管理、授权或文件权限。由 DBA 执行，密码用参数化管理工具设置，不要照抄占位符：

```sql
CREATE DATABASE mes CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;
CREATE USER 'mes_app'@'10.%' IDENTIFIED BY '<强随机密码>';
GRANT SELECT, INSERT, UPDATE, DELETE, CREATE, ALTER, DROP, INDEX, REFERENCES
ON mes.* TO 'mes_app'@'10.%';
```

将主机范围收窄到应用网段或主机。不要授予 `GRANT OPTION`、`FILE`、`PROCESS` 或全局 `*.*`。若组织要求迁移账号和运行账号分离，需要先改造当前单数据源/Flyway 配置，不能只在文档层假定已经分离。

备份账号可只授予当前 schema 的 `SELECT`、`SHOW VIEW`、`TRIGGER`；恢复账号需要目标 schema 的数据和 DDL 权限。账号应分别管理和轮换。

### 3.1 Windows 本地开发数据库

已安装 MySQL 8、但不希望修改现有 3306 实例时，可在仓库根目录运行：

```powershell
.\deploy\setup-dev-mysql.ps1
.\deploy\run-dev.ps1
```

脚本在 `%LOCALAPPDATA%\MES-JAVA\mysql` 创建仅监听 `127.0.0.1:3307` 的独立实例，创建 `mes` 库和 `mes_app` 账号，并把随机数据库密码写入 Git 已忽略的 `deploy/.env.local`。默认同时写入当前 Windows 用户环境，使用 IDE 启动时需先重启 IDE；不希望写入用户环境可传入 `-SkipUserEnvironment`。`run-dev.ps1` 会把这些值直接注入当前后端进程并启用 MySQL；需要本机已配置 Java 21、Maven 3.9+。

本地引导密码仅用于首次创建 `admin`，不覆盖已有账号。首次登录后应立即修改密码，并从 `deploy/.env.local` 删除 `MES_BOOTSTRAP_ADMIN_PASSWORD`。开发实例不得直接用于生产。

## 4. 容器部署

```powershell
Copy-Item deploy/.env.example deploy/.env
# 用受控编辑器填写 deploy/.env，确保该文件不进入版本库
docker compose --env-file deploy/.env -f deploy/docker-compose.yml up -d --build
docker compose --env-file deploy/.env -f deploy/docker-compose.yml ps
```

Compose 启动 MySQL 8，启用 `utf8mb4`、健康检查和持久卷；`mes` 在 MySQL 健康后启动。SQLite 保存在 `mes-data` 卷，MySQL 保存在 `mysql-data` 卷。容器内应用以非 root 用户运行，`/app/data` 可写。

`/api/system/health` 是进程探活；`/api/system/readiness` 只有 MySQL 与 SQLite
均可查询时才返回 200。两者都不证明采集设备和 WebSocket 正常，上线验收还要检查
日志、业务查询和运行指标。Linux amd64 完全离线交付见
[`deploy/OFFLINE-LINUX.md`](../deploy/OFFLINE-LINUX.md)。

首次启动成功并创建 `admin` 后，在页面轮换密码，将 `.env` 中 `MES_BOOTSTRAP_ADMIN_PASSWORD` 清空，再重建 `mes` 容器。已有 `admin` 不会被引导变量覆盖。

## 5. Windows 目录发布

在仓库根目录执行：

```powershell
.\deploy\publish.ps1
```

脚本依次运行前端测试/构建和后端测试/打包，产物位于 `deploy/dist`。阅读其中 `STARTUP.md`，通过服务账号环境设置变量后运行 `start.bat`。脚本会拒绝禁用业务库、空 MySQL 密码、空 Origin 或不安全的生产 Cookie；不会把秘密写入文件。

推荐用 Windows 服务包装器托管 Java 进程，并设置正常停止超时大于 20 秒；不要用强杀作为常规停机方式。

## 6. Flyway 运行与失败处置

应用启用业务库后，系统域迁移先运行，生产域迁移随后运行，历史表分别为：

- `flyway_schema_history_system`
- `flyway_schema_history_production`

升级前先做双库备份并确认可恢复。迁移失败时：

1. 保持应用停止，保存完整日志和失败 SQL；
2. 核对目标数据库、账号权限、MySQL 版本、磁盘空间和历史表；
3. 在测试副本复现并修正为新的前向迁移；
4. 只有确认数据库对象与历史记录实际状态后，才由 DBA 评估 `flyway repair`；
5. 不建议手工删除历史记录、修改已发布迁移或对生产库执行未经验证的危险回滚。

若迁移已经部分提交，MySQL DDL 不保证像普通事务一样整体回滚。优先从升级前备份恢复到隔离实例验证，再决定前向修复或整库恢复。

## 7. SQLite WAL

应用启动时设置 `journal_mode=WAL`、`synchronous=NORMAL` 和 busy timeout。运维注意：

- `mes.db`、`mes.db-wal`、`mes.db-shm` 在运行时可能同时存在；
- 不要在应用运行时只复制 `mes.db`；
- 使用 SQLite CLI 的 `wal_checkpoint(FULL)` 加 `.backup`，或使用 [`deploy/backup.ps1`](../deploy/backup.ps1)；
- 保证数据卷可写、空间充足，不把数据库放在不可靠的网络共享目录；
- 恢复前必须停止应用，避免旧 WAL 覆盖恢复文件。

## 8. TLS、反向代理、Cookie 与 Origin

外部只暴露 HTTPS。反向代理把 `/`、`/api/` 和 `/hubs/realtime` 转发到 5100，并支持 WebSocket Upgrade；扫码枪需要时单独限制来源网络访问 6001。

Nginx 关键片段示例：

```nginx
location / {
    proxy_pass http://127.0.0.1:5100;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto https;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
}
```

生产设置 `MES_SESSION_COOKIE_SECURE=true`。`MES_ALLOWED_ORIGINS` 必须是浏览器地址栏的精确 Origin，例如 `https://mes.example.com`；不要使用 `*`，不要附加路径或结尾斜杠。代理应保留 `X-XSRF-TOKEN` 请求头和 Cookie。

## 9. 双库备份与恢复

安装 MySQL 8 Client 和 SQLite CLI 并加入 Windows `PATH`。目录发布可直接执行：

```powershell
.\deploy\backup.ps1 `
  -MySqlHost db.example.internal `
  -MySqlDatabase mes `
  -MySqlUser mes_backup `
  -SQLitePath D:\MES\data\mes.db
```

脚本安全提示输入 MySQL 密码，使用 `mysqldump --single-transaction`，对 SQLite 先执行安全 checkpoint 再 `.backup`，并校验备份库。双库没有跨库快照事务；应在业务低峰执行，并把整个时间戳目录作为同一备份集保存、加密和异地复制。

恢复会覆盖双库，先停止应用并在隔离环境演练：

```powershell
.\deploy\restore.ps1 `
  -BackupDirectory D:\MES-Backup\20260814-020000 `
  -MySqlHost db.example.internal `
  -MySqlDatabase mes `
  -MySqlUser mes_restore `
  -SQLitePath D:\MES\data\mes.db `
  -ApplicationStopped `
  -ConfirmRestore
```

没有 `-ConfirmRestore` 和 `-ApplicationStopped` 时脚本拒绝写入。脚本在覆盖前另建安全备份，但恢复仍不是跨库原子事务；任一步失败时保持应用停止，保留安全备份，并从同一备份集重新处置。容器命名卷应由运维先映射到受控备份主机路径，或在维护窗口导出到主机，再使用同样的完整性检查流程。

## 10. 断线、设备与队列故障

### WebSocket 断线

前端会从 1 秒开始指数退避重连，最长约 30 秒。持续断开时检查 TLS 证书、代理 Upgrade 头、Session 是否有效、Origin 是否匹配，以及浏览器 401/403。

### PLC 或扫码枪故障

Modbus 失败会关闭连接并在后续轮询重连，设备进入离线并产生通讯报警。检查设备供电、IP/端口、VLAN/防火墙、从站号、点表和字序。不要通过本系统尝试写 PLC。扫码枪检查 TCP Client 目标、6001 网络白名单、来源 IP 与 `ScannerBindings`。

新设备接入前可按 [`Modbus现场调试.md`](Modbus现场调试.md) 启用受限只读探针，
完成单次读取、短时轮询和 JSON/CSV 验收导出；调试结束后应关闭探针。

### 队列指标

`GET /api/system/info` 暴露 `queueSize`、`droppedFrames` 和 `realtimeClients`。重点告警：

- `queueSize` 持续增长：SQLite 写入、磁盘延迟或锁竞争可能异常；
- `droppedFrames` 增加：队列已满并丢弃最旧快照，应立即检查存储性能；
- `realtimeClients` 异常为零：检查代理、Session 和前端连接。

这些是进程内累计值，重启后会重置，当前项目未内置 Prometheus 导出或自动告警平台。

## 11. 优雅停机

正常停止时后台服务按“扫码 -> 采集 -> 清理 -> 处理”反序退出，处理服务最后刷新队列和缓冲。操作步骤：

1. 停止新工单操作并观察队列回落；
2. 使用服务管理器、`docker compose stop mes` 或正常终止信号；
3. 至少等待 Spring 20 秒停机阶段完成，查看“停止后台服务”日志；
4. 再停止 MySQL或执行维护。

断电、进程崩溃和强杀不保证完成缓冲刷新，因此仍需 UPS、WAL 和备份。

## 12. 升级与回滚

1. 阅读变更，确认数据库迁移和环境变量；
2. 运行测试并在与生产同版本的 MySQL/SQLite 副本演练；
3. 记录当前镜像/JAR、`devices.json`、环境配置摘要和双库备份；
4. 优雅停止，升级应用，观察两套 Flyway、健康接口、登录、关键查询、队列和设备连接；
5. 失败时不要只回滚 JAR：若新迁移已改变 schema，先判断旧版本是否兼容；
6. 不兼容时保持停机，使用升级前同一双库备份集恢复，再部署旧镜像/JAR；
7. 验证用户权限、工单、追溯、原始报警/遥测和 3D 实时状态后再恢复业务。
