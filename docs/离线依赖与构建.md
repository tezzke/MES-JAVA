# 离线依赖与可复现构建

## 1. 基线

项目运行期不从公网下载资源，不使用 CDN、远程字体或外部业务 API。联网仅发生在受控构建机准备 Maven、npm 和容器镜像制品时；Linux 目标机只加载已校验的镜像包。

固定工具链如下：

- Java 21，Spring Boot 3.2.5；
- Maven Wrapper 3.9.11，发行包使用 SHA-256 校验；
- Node.js 20.19.x、npm 10.8.2；
- 前端直接依赖使用精确版本，`package-lock.json` 中每个包必须包含 `integrity`；
- Flyway 10.17.0、SQLite JDBC 3.45.3.0 保持不变，避免未经迁移演练的大版本切换。

## 2. 前端依赖

构建机执行：

```bash
cd frontend
npm run verify:lock
npm ci
npm test
npm run build
```

禁止使用 `npm update` 或删除锁文件后直接提交。升级依赖时应一次只处理一组相关包，重新生成完整锁文件，审查许可证和安全公告，并完成页面回归。ECharts 等大版本升级不得混入常规部署改动。

内网需要自建 npm 代理时，可在部署组织自己的用户级 `.npmrc` 中设置 Nexus/Artifactory 地址；仓库不保存内部地址或凭据。

当前 `echarts 5.6.0` 的上游审计包含一项 moderate XSS 公告，自动修复会升级到不兼容的 6.x。本次为保持现场版本稳定不做强制大版本切换；页面不得把用户输入作为 ECharts HTML formatter，后续应在独立兼容性任务中升级并回归所有图表。

## 3. 后端依赖

联网构建机首次准备缓存：

```bash
cd backend
./mvnw -B dependency:go-offline
./mvnw -B dependency:resolve-plugins
./mvnw -B test
```

验证缓存可离线使用：

```bash
./mvnw -B -o test
./mvnw -B -o package -DskipTests
```

Windows 使用 `mvnw.cmd`。Maven Wrapper 首次运行需要取得已固定并校验的 Maven 发行包；目标运行服务器不需要 Maven。企业内网镜像应通过用户或 CI 的 `settings.xml` 配置，密码不得进入仓库。

## 4. 容器制品

目标机不执行 `docker build`，不拉取镜像。离线包必须包含应用、MySQL、Nginx 镜像 tar、版本清单和 SHA-256 文件。安装前先校验清单，再执行 `docker load` 和：

```bash
docker compose --pull never up -d
```

基础镜像使用明确 patch 版本；每个交付包同时记录实际镜像 digest。镜像升级必须重新运行后端、前端、迁移和离线启动烟测，不能只移动 `latest` 标签。

## 5. 运行期网络边界

运行期只允许：

- 浏览器或内网反向代理访问 MES HTTP 端口；
- MES 访问同 Compose 网络中的 MySQL；
- MES 按白名单访问 PLC Modbus TCP；
- 已授权扫码设备访问扫码 TCP 端口。

防火墙应拒绝容器访问公网 DNS、软件仓库和公共镜像仓库。若完全断网后健康检查、登录、WebSocket、Modbus 读取和双库写入仍可工作，才视为离线验收通过。
