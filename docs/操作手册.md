# MES 操作手册

本文按当前前端功能说明日常操作。菜单是否可见、按钮是否可用取决于账号权限；无权限时联系系统管理员，不要共用管理员账号。

## 1. 首次管理员引导

系统没有默认管理员密码。空业务库首次启动前，运维人员需通过安全环境变量设置一次性强密码：

```powershell
$env:MES_BOOTSTRAP_ADMIN_PASSWORD = '<强随机密码>'
```

应用就绪后仅在不存在 `admin` 用户时创建管理员。确认可以登录后：

1. 进入“用户管理”，编辑 `admin`；
2. 在“新密码”中设置新的独立强密码并保存；
3. 退出后用新密码重新登录验证；
4. 从服务环境和秘密管理中删除 `MES_BOOTSTRAP_ADMIN_PASSWORD`，重启不会覆盖已有管理员。

## 2. 登录与退出

打开系统地址进入登录页，输入用户名和密码。登录成功后浏览器持有服务端 Session Cookie；请勿复制 Cookie 或 CSRF Token。页面右上角“退出”会结束会话。公共终端使用后应关闭浏览器。

如果出现 401，重新登录；出现 403 表示账号缺少权限或请求的 CSRF 校验失败。连续登录失败可能触发账号锁定信息，需管理员检查账号状态。

## 3. 用户、角色、权限和菜单

建议按“角色定义 -> 分配权限 -> 创建用户 -> 分配角色 -> 配置菜单”顺序操作。

### 3.1 角色与权限

1. 在“角色管理”新增角色，填写稳定的角色编码和名称。
2. 点击“分配权限”，按最小权限原则选择权限码。
3. 生产操作员通常只需要读取主数据/工单、执行任务、查看追溯和处置报警；不要授予用户或角色管理权限。
4. `SYSTEM_ADMIN` 控制生产环境 Swagger 访问，不等于自动包含其他权限。

### 3.2 用户

在“用户管理”新增用户，设置显示名、初始密码和启用状态，再点击“分配角色”。停用人员账号应优先禁用；删除前确认审计与历史记录仍满足留存要求。

编辑用户时密码留空表示不修改密码；填写后会重置密码。管理员重置他人密码后，应通过受控渠道交付，并要求首次使用后再次轮换。

### 3.3 菜单

菜单记录包含名称、路径、权限码、排序和启用状态。路径必须对应前端已有路由；新增数据库菜单不会自动创建新页面。菜单只控制导航可见性，服务端权限仍决定接口能否调用。

## 4. 生产主数据

“生产主数据”支持物料、产品、BOM、BOM 明细、车间、产线、工位、设备绑定、工序、工艺路线和路线步骤。

推荐维护顺序：

1. 物料、产品；
2. 车间、产线、工位；
3. 工序；
4. BOM 及 BOM 明细；
5. 工艺路线及路线步骤；
6. 工位与设备绑定。

页面使用统一字段：编码、名称、主引用 ID、次引用 ID、顺序、数量、属性 JSON 和启用状态。引用字段填对应记录的数值 ID；属性必须是合法 JSON 对象。编辑时系统携带版本号，若提示并发冲突，刷新后核对他人修改再重试。

## 5. 工单下达

1. 进入“生产工单”，点击“新建工单”。
2. 填写唯一工单号、产品 ID、工艺路线 ID、批次号和大于零的计划数量。
3. 保存后工单为 `DRAFT`，此时可编辑或删除。
4. 核对主数据和数量后点击“下达”。下达会按路线生成任务，状态变为 `RELEASED`。

已下达工单不能通过当前页面回退为草稿。状态转换由服务端状态机控制。

## 6. 任务扫码、报工与完工

在工单行点击“详情/任务”：

1. `READY` 任务点击“扫码开工”，输入现场条码并提交；首个任务开工后工单进入进行中。
2. `IN_PROGRESS` 任务点击“报工”，输入合格数、不良数和可选条码。两类数量必须非负、合计大于零，累计不得超过计划数量。
3. 任务完成现场操作后点击“完工”，输入条码并提交。
4. 按路线顺序处理后续任务。全部任务完成后工单完成。

按钮提交期间不要重复点击。并发操作若触发版本冲突，应关闭详情、刷新工单和任务状态后再决定是否重做。

## 7. 生产追溯

“生产追溯”可按批次号或条码查询工单、任务、事件类型、合格/不良数量和发生时间。该页面查询 MySQL 中由生产任务操作产生的追溯事件。

“实时扫码追溯”展示网口扫码枪写入 SQLite 的原始扫码记录。两者来源和用途不同，当前系统不会自动把所有原始扫码匹配到生产工单。

## 8. 报警处置

“SQLite 报警”用于查看采集侧原始报警及其触发/恢复状态。“报警处置”用于业务闭环：

1. 以原始报警 ID 执行“确认源报警”，创建 `ACKNOWLEDGED` 处置记录；
2. 可“指派”处理人进入 `ASSIGNED`，也可从已确认状态直接解决；
3. 填写处理结果后“解决”进入 `RESOLVED`；
4. 复核后“关闭”进入 `CLOSED`。

处置记录只引用原始报警 ID。操作前应在“SQLite 报警”核对设备、点位、级别和恢复情况。

## 9. 3D、实时监控和历史

- “生产总览”显示设备实时状态和活动报警。
- “3D 车间”按设备档案的位置渲染 Three.js 场景，可查看设备状态。
- “历史曲线”查询 SQLite 遥测历史。
- 侧栏底部显示 WebSocket 实时通道状态；断开后客户端会自动重连。

实时通道断开不代表历史数据一定丢失。先刷新页面并检查网络；持续断开时由运维人员按 [部署与运维](部署与运维.md) 排查。

## 10. Modbus 单设备验收

拥有 `MODBUS_PROBE` 权限且运维已启用目标网段后，可进入“Modbus 现场探针”：

1. 填写 IP、端口、Unit ID、功能码和寄存器范围，先测试 TCP 连接；
2. 按设备手册选择数据类型、字节序、字序、缩放和偏移，执行单次读取；
3. 对照请求/响应 Hex 与寄存器 Hex/十进制确认格式；
4. 启动不超过 60 秒的短时轮询，操作设备并观察值变化；
5. 导出 JSON/CSV 留作验收记录，停止轮询。

该页面只允许功能码 03/04，不会写 PLC。完整地址规则、安全白名单和错误说明见
[Modbus现场调试](Modbus现场调试.md)。

## 11. 密码轮换

当前没有独立“修改我的密码”页面。具有 `USER_WRITE` 的管理员可在“用户管理”编辑用户并填写新密码。建议：

- 管理员和高权限账号定期轮换，人员变动时立即轮换或禁用；
- 使用密码管理器生成并保存独立强密码，不通过日志、脚本或聊天明文传递；
- 轮换 bootstrap 管理员后删除引导变量；
- 至少保留两个受控管理员账号，避免单一账号失效造成锁定；
- 完成轮换后退出旧会话并重新登录验证。
